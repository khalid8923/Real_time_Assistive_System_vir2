# CaptionBridge

رفيقك الذكي في المحاضرات الجامعية. يستمع لكلام الدكتور، يحوّله لنص عربي لحظيًا، ثم يحوّل النص إلى مواد دراسية كاملة — ملخصات، خرائط ذهنية، جداول مقارنة، معادلات، كروت مراجعة، والكثير.

**الرابط المباشر:** https://real-time-assistive-system-vir2.vercel.app

---

## ليه عملت المشروع ده

شوفت صاحبتي — صماء من وهي صغيرة — بتقعد محاضرتين كاملين وتخرج **بدون حاجة**. مش لأنها مش مركزة. لأن مفيش حاجة تتركز عليها. مفيش مترجم إشارة لكل الفصل. مفيش ترجمة نصية. الدكتور بيكمل، وهي بتتأخر دقيقتين، بعده خمسة، بعدها خلاص.

الجامعات المصرية ماعندهاش البنية التحتية دي. والأدوات اللي موجودة (Otter، Live Transcribe) **غالية، مصممة للإنجليزي، ومش بتفهم العربي المصري**. حتى Google Web Speech API — اللي المفروض مجاني — **محجوب من مزودي الخدمة في مصر**.

فعملت الحاجة اللي كنت عايزها تكون موجودة. بدأ كمشروع تخرج في كلية الحاسبات والذكاء الاصطناعي بجامعة حورس. **اتوسّع** لما لاحظت إن التحليل الذكي يساعد كل طالب: اللي نام في المحاضرة، اللي بيراجع قبل الامتحان بيومين، واللي لغته الأولى مش العربي.

إعادة التسمية إلى **"رفيقك الذكي في المحاضرات الجامعية"** بتعكس ده. نفس الأداة، جمهور أوسع.

## اللي بيعمله

### التسجيل والتحويل
- **تحويل عربي لحظي** — كلام الدكتور لنص في مقاطع 6 ثواني، باستخدام Hakim AI مع fallback تلقائي لـ Groq Whisper
- **تمييز ذكي للنص** — الإنجليزي والأرقام والكلمات المفتاحية بتتلون تلقائيًا

### مواد دراسية بالذكاء الاصطناعي (كلها من نص المحاضرة)
- **ملخص ذكي** — عنوان + نظرة عامة + نقاط رئيسية + خلاصة
- **خريطة ذهنية** — شجرة موضوعات بـ React Flow
- **معجم أكاديمي** — كل مصطلح تقني مع تعريف مبسّط
- **كلمات مفتاحية** — مصنفة حسب النوع مع نجوم الأهمية
- **كروت مراجعة** — سؤال/جواب جاهزة
- **رادار المهام** — يلتقط تلميحات الامتحانات والواجبات
- **أسئلة القاعة** — يستنتج اللي الطلاب البعيدين سألوه

### شرح بصري
- **جداول مقارنة** — "let vs var"، "TCP vs UDP"، مستخرجة من نص المحاضرة نفسها
- **خريطة تشبيه** — "الكاش زي المكتب" → جدول تطابق + نقاط الانهيار
- **معادلات تفاعلية** — عرض بـ KaTeX، سلايدرز حية، منحنى مباشر
- **المنظر المفكّك** — طبقات OSI، TCP/IP، مراحل الـ Compiler
- **خريطة حجج** — أطروحة، ادعاءات، أدلة، اعتراضات، ردود
- **مستكشف السبب والنتيجة** — علاقات X → Y مع كشف الحلقات
- **مخططات عمليات** — Mermaid diagrams
- **ارسمها لي** — يختار شكل الرسم المناسب تلقائيًا

### الحساب والمحاضرة
- تسجيل بالإيميل + تحقق إلزامي
- استعادة كلمة المرور
- حفظ/تحميل المحاضرات من السحابة
- لوحة أدمن لإدارة المستخدمين
- إشعارات Telegram — الطالب يضغط زر، الدكتور يستقبل رسالة مع خيارات رد

## الـ Stack

| الطبقة | الاختيار | السبب |
|--------|----------|-------|
| Framework | Next.js 16 (App Router + Turbopack) | Server Components + Streaming + API routes ناضجة |
| Language | TypeScript 5.9 | strict mode من غير أي `any` |
| UI | React 19 + Tailwind v4 | أحدث features + محرك Tailwind الجديد |
| Components | مكتوبة يدويًا (shadcn-style) | بدون lock-in لمكتبة UI معينة |
| Animation | Motion | تحكم دقيق في الـ layout والـ presence |
| Diagrams | React Flow + Mermaid | React Flow للخرائط التفاعلية، Mermaid للمخططات الثابتة |
| Math | KaTeX + expr-eval | KaTeX يعرض، expr-eval يحسب مباشرة |
| Charts | Recharts | متوافق مع React 19 |
| Auth | Better Auth | self-hosted، بدون تبعية خارجية، متوافق مع Kysely |
| Database | Turso (libSQL) | SQLite سحابي — الـ free tier كافي لمشروع تخرج |
| STT | Hakim AI → Groq Whisper | Hakim أفضلمع العربي المصري، Groq نسخة احتياطية |
| LLM | NVIDIA NIM → Groq → Gemini | سلسلة fallback ثلاثية، كلها free |
| Deployment | Vercel | zero-config لـ Next.js |

## البدء السريع

### المتطلبات

- Node.js 20+
- قاعدة بيانات Turso (الـ free tier كافي)
- مفاتيح API لمزود STT واحد على الأقل (Hakim أو Groq) ومزود LLM واحد (NVIDIA أو Groq أو Gemini)

### التثبيت

```bash
git clone https://github.com/khalid8923/Real_time_Assistive_System_vir2.git
cd Real_time_Assistive_System_vir2
npm install
```

### الإعداد

انسخ `.env.example` إلى `.env.local` واملأ القيم.

### التشغيل

```bash
npm run dev
```

افتح http://localhost:3000. المتصفح هيطلب إذن الميكروفون أول مرة.

## قرارات تصميم تستحق التوضيح

**ليه Turso مش Postgres.**
الـ free tier بيغطي الاستخدام المتوقع. SQLite من جواه، فالمigrations بسيطة، وlibSQL شغال من edge functions. لأي استخدام أكبر من مئات المستخدمين، سأتحول لـ Neon أو Supabase Postgres.

**ليه Hakim AI كأساسي مش Whisper.**
Hakim متظبط للعربي — بما فيه المصري — وبيرجع ناتج أنضف في المجال ده. Whisper أسرع وأوسع توفرًا، فبيفضل كـ fallback. السلسلة بتلف بين مفتاحين Hakim بـ round-robin وبتنزل لـ Groq بس لما الاتنين يفشلوا.

**ليه تلات مزودين LLM.**
مافيش مزود free-tier موثوق لوحده. NVIDIA NIM بيدي 40 request/min لكل مفتاح. Groq بيدي 1000/day لكل موديل. Gemini بيدي 1500/day. بالتراكم، محاضرة كاملة نادرًا ما تفشل، وأنا مش بدفع مليم.

**ليه rate limit scope لكل route.**
النسخة الأولى كانت عداد واحد لكل الـ routes. حد 10/min على `/api/chat` كان فعليًا حد 10/min على التطبيق كله. فصل الـ scope حل المشكلة.

**ليه عنصر بصري متحرك في صفحات الـ auth.**
التسجيل هو المكان اللي الناس بتقرر فيه تثق في المنتج ولا لأ. فورم ثابت عادي، لكن استجابة بصرية صغيرة مصممة كويس بتقول إن الأداة اتبنت بنية. بيحترم `prefers-reduced-motion` ومش بيعطّل الفورم أبدًا.

**ليه RTL-first.**
الجمهور المستهدف بيقرأ عربي. RTL هو الافتراضي، مش فكرة لاحقة.

## قيود معروفة

- **الحصص المجانية.** حوالي 30 مستخدم نشط يوميًا قبل أي مزود AI يبدأ يعمل throttle.
- **إيميل التحقق بيروح Spam.** حسابات Gmail الشخصية عندها سمعة سيئة للإيميلات الآلية. دومين مخصص مع Resend أو Brevo بيحل ده.
- **Google OAuth.** مخفي في الواجهة الإنتاجية. الـ client الحالي شغال محليًا بس Vercel عندها client ID قديم.
- **كشف الصوت تجريبي.** بيقرأ dB المحيط، مش تصنيف أحداث حقيقي.
- **مفيش tests.** كل حاجة اتأكدت منها يدويًا. مش مثالي، بس صادق.
- **Rate limiting على نسخة واحدة.** بيستخدم `Map` في الذاكرة. على multi-region يحتاج Redis.
